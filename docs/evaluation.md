# MVP 검색·갱신 검증

검증일: 2026-09-27. Python 3.12 / macOS arm64. 데이터는 `examples/vault/`의 가상 노트 5개, `scripts/evaluate.py`의 한국어 질문 20개다. 실제 사용자 노트를 읽거나 외부 생성 API에 전송하지 않았다.

## 자동 동작 검사

`uv run pytest -q`: **29개 통과**. 실제 macOS FSEvents 검사도 포함했다. 제한된 실행 샌드박스에서는 FSEvents 스트림이 차단되어, 권한이 허용된 로컬 테스트 프로세스에서 확인했다.

검사 범위: 읽기 전용·제외/경로 경계, 정확한 원문 줄 위치, 변경 없는 검사, 재저장/교체/연속 저장/이동/삭제, 시작 시 변경 복구, 처리 중 재변경, iCloud placeholder/읽기 실패, 깨진 YAML과 링크, 필터 일관성, 실제 sqlite-vec 조회, RDF·SHACL, 인용 검증 실패 복귀, 관계 검토와 출처 변경, 모델 변경, 로컬 API 접근 경계와 데이터 삭제.

Ruff 검사·포맷 검사와 `node --check web/app.js`를 통과했다. RDFLib 및 FastAPI 테스트 클라이언트의 의존 API 폐기 예정 경고가 발생한다. 기능 실패는 없으며 현재 의존성은 `uv.lock`에 고정되어 있다.

## 실제 로컬 모델로 검색 비교

모델: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384차원. FastEmbed 0.7.4, ONNX CPU 2스레드. 원문과 질의의 벡터는 실제 모델로 생성했다. 단위 테스트의 결정적 벡터 대역은 이 평가에 사용하지 않았다.

| 검색 경로 | 정답 근거 Hit@5 | MRR@5 | 엄격한 주석 기준 Precision@5 | 반환 근거 원문 검증 |
|---|---:|---:|---:|---:|
| 단어 | 20/20 | 0.942 | 0.263 | 100% |
| 단어 + 벡터 | 20/20 | 0.785 | 0.209 | 100% |
| 단어 + 벡터 + 관계 | 20/20 | 0.645 | 0.200 | 100% |

- **Hit@5:** 질문별로 지정한 정답 문단이 상위 5개 안에 있는지 측정했다.
- **MRR@5:** 첫 정답 문단의 역순위 평균이다. 높을수록 정답이 앞에 있다.
- **Precision@5:** 지정한 정답 문단만 관련 있다고 보는 엄격한 주석 기준이다. 문맥 보완용 근거도 비정답으로 계산하므로 완전한 의미적 적합도 평가가 아니다.
- **원문 검증:** 반환한 문단의 현재 파일 해시·줄 범위·문단 해시가 일치했다는 뜻이다. 생성 답변의 사실 정확도 100%라는 뜻이 아니다.

이 표본에서는 단어 검색이 순위 면에서 가장 좋다. 하이브리드 구성의 일반적인 우위는 확인하지 못했다. 생성 모델의 답변 정확성·모순 처리·실제 사용자의 질문 회수율은 아직 측정하지 않았다.

## 초기 문제와 수정

처음에는 제목만 있는 문단과 frontmatter도 발췌 후보에 넣고 검색 경로에 같은 순위 가중치를 적용했다. 연결이 많은 문서가 과도하게 올라와 세 경로 결합의 Hit@5가 13/20으로 떨어졌다.

제목·속성만 있는 문단은 최종 발췌에서 제외하고, 단어 1 / 의미 0.5 / 관계 0.15로 가중 RRF를 적용했다. 위 결과는 **같은 개발 표본으로 수정 후 확인한 값**이다. 독립 검증이나 실제 볼트에서의 품질을 대체하지 않는다. 추가 조정 전에 실제 질문으로 별도의 평가셋을 만들어야 한다.

- 초기 측정: [evaluation-initial.json](evaluation-initial.json)
- 현재 측정과 질문별 순위: [evaluation.json](evaluation.json)

## 갱신 비용

| 측정 | 최초 5개 노트 색인 | 변경 없는 메타데이터 대조 |
|---|---:|---:|
| 본문 읽기 | 10회 | 0회 |
| 임베딩 입력 수 | 34개 | 0개 |
| 색인/대조 경과 시간 | 약 0.819초 | 약 0.0009초 |
| 프로세스 CPU 시간 | 약 1.010초 | 약 0.0006초 |
| OS 보고 디스크 입력 블록 증가 | 0 | 0 |

최초 색인은 처리 전후 안정성·최신 해시를 확인하므로 파일당 2회 읽었다. 위 시간은 모델 파일 다운로드를 포함하지 않는다. OS 캐시가 있는 작은 표본의 단일 측정이며, 디스크 입력 블록 0이 물리 디스크 활동이 전혀 없었다는 보장은 아니다. 모델 추론의 다중 스레드 때문에 CPU 시간이 경과 시간보다 길 수 있다.

변경 없는 검사에서 본문·임베딩·RDF 재검증 함수를 호출하면 실패하도록 한 회귀 검사도 통과했다. 실제 볼트의 파일 수·본문 길이·iCloud 상태에 따른 Mac 부하는 아직 측정하지 않았다.
